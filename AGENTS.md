# CampusSync engineering rules

- Treat `docs/PRODUCT_CONTRACT.md`, `docs/ARCHITECTURE.md`, and `docs/DELIVERY.md` as the implementation boundaries.
- The local checkout and GitHub repository are authoritative; Lovable is not a deployment target.
- Never fabricate extraction, an official notice, or institutional verification.
- Samples are fictional and must be visibly labelled.
- Keep raw notice contents transient, secrets server-side, and all provider work behind the adapter boundary.
- Test the local workflow and calendar output after each coherent change.
